# RateWise AI

RateWise AI is a stateless AI product decision assistant. A user takes or uploads one product label image, the backend sends the image directly to Gemini Vision for label reading and analysis, and returns a structured rating, decision, scores, short reason, warnings, and one better alternative.

No accounts, database, history, saved scans, or recent scans are included.

## Structure

```text
ratewise_ai/
  app/
    src/
    assets/
    package.json
    tsconfig.json
  backend/
    src/
    package.json
```

The React Native / Expo project root is `app/`. Run frontend commands from `ratewise_ai/app`, not the repository root. Native Android files are generated by Expo when you run `npm run android`.

## Run Instructions

Backend:

```powershell
cd backend
npm install
Copy-Item .env.sample .env
npm run dev
```

Before live scans, set `GEMINI_API_KEY` and `GEMINI_MODEL` in the backend environment. The Gemini key stays server-side.

Frontend:

```powershell
cd app
npm install
Copy-Item .env.example .env
npm start
```

For Android emulator development, `EXPO_PUBLIC_API_BASE_URL=http://10.0.2.2:8080` points to the local backend. For iOS simulator or web, use `http://localhost:8080`.

## React Native App

The app preserves the original mobile flow: splash, scan home, processing steps, result overview, expandable details, one alternative card, and warning card only when needed.

```powershell
cd app
npm install
npm start
```

For native builds:

```powershell
npm run android
npm run ios
```

Set `EXPO_PUBLIC_API_BASE_URL=https://YOUR_API_HOST` for production mobile builds. Backend secrets must remain only in the backend environment.

## Backend

```powershell
cd backend
Copy-Item .env.example .env
npm install
npm run dev
```

Required environment variables:

- `GEMINI_API_KEY`
- `GEMINI_MODEL`
- `APP_ORIGIN` required in production
- `PORT` optional; Elastic Beanstalk sets this automatically

Required Gemini format:

```env
NODE_ENV=production
APP_ORIGIN=https://YOUR_FRONTEND_HOST
GEMINI_API_KEY=your_gemini_api_key
GEMINI_MODEL=your_available_gemini_vision_model
```

Check configuration at:

```powershell
curl https://YOUR_API_HOST/health
```

`config.missingRequired` must be empty before live product analysis can run.

## API

### `POST /analyze`

Multipart form upload:

- `image`: product back-label image

Response:

```json
{
  "rating": 4.4,
  "decision": "BUY",
  "reason": "Good ingredients and balanced nutrition.",
  "trustScore": 92,
  "healthScore": 85,
  "valueScore": 78,
  "ingredientsAnalysis": [],
  "warnings": [],
  "expiryAnalysis": "",
  "alternativeProduct": {}
}
```

## Production Notes

- Keep the server behind HTTPS with Nginx or a production load balancer.
- Set `APP_ORIGIN` to the app or web origin in production.
- Keep `GEMINI_API_KEY` in backend environment variables only.
- Uploaded images are processed in memory and are not stored.
- Gemini Vision receives the uploaded image bytes directly; images are processed in memory and are not stored.
